# 斗场 · AI Arena

规则由你写，阵容由你挑。多个模型同时开局、各自思考、各自提交，全员到齐后由裁判统一裁决——
每一句话都进事件流，可逐帧回放。

```
rulesets/*.md ──编译──> Blueprint（回合数 / 提交项 / 评分维度 / 胜负方式）
                              │
src/engine/round.ts      回合状态机（纯函数，无 I/O，可复现）
src/engine/runtime.ts    执行副作用：并行调度、调模型、落库、推事件
src/app/arena/[id]       SSE 观战台（事件流的 reducer）
```

## 快速开始

```bash
bun install
bun run db:migrate      # 建表 + 灌默认接入方 + 同步 rulesets/
bun run dev             # http://localhost:3000
```

**不需要任何 API Key 也能跑通全流程**：内置「演练场」与四个演练体模型。
在 /setups 填了真实 Key 并拉取模型后，随机配对会自动优先使用真实模型。

## 慢模型与坏输出

一场对局必须等全员交齐，所以运行时有几道看门狗（都可用环境变量调）：

- `ARENA_CALL_TIMEOUT_MS`（默认 180s）：单次调用硬超时，超时该方本轮弃权。
- `ARENA_NO_SUBMIT_MS`（默认 150s）：这么久还没开始写提交块，判定为跑偏，直接截断。
- 重复片段检测：同样的 60 字窗口重复 6 次以上，判定为在原地打转，立刻截断。
- 裁判调用走 provider 原生 JSON 模式；解析失败会带着原答案重试一次严格 JSON。

## 一局的时序

1. 选规则、编队（1v1 / 1v2 / 1v3 / 2v2 / 混战）、定裁判（默认自动）、掷种子。
2. 每一轮：**所有选手并行**发起，思考流实时推给观众，提交内容落库。
3. 全员「就位」或「弃权」后，才把整轮材料交给裁判——先交不构成优势。
4. 裁判盲化打分（只看到 A / B / C…），给出本轮判词与公开战况。
5. 累计分；打满则按分差决定是否进入一轮加时（突然死亡）。

## 观战台怎么读

- 每个座位头部是身份：显示名、厂商、真实模型 id、思考档位（含显式预算）；次行是温度、输出上限，右侧是本次调用的 token 与耗时。
- **思考**与**出招**分成两个区块：思考是灰底、按原文换行，超过 900 字可展开；出招是绿底、按槽位分字段（数字右对齐、选项成 chip、暗项带 🔒），长文本不会只剩一行省略号。
- 历史裁决同样按「每方一块」：字段化出招 + 可折叠思考（默认收起）；评分给出各维度分与备注；裁判自己的推演也能展开。
- 页头常驻裁判身份（显示名 / 厂商 / 模型 id / 思考档位）。裁判在开局那一刻冻结并写进对局，
  所以第一轮裁决之前就能看到是谁在裁；只有 v6 之前的老对局才显示「未记录」。
- 只有实时座位卡会把思考自动滚到底；历史默认收起，避免逐轮刷屏。

## 三条硬规则

- **思考只给观众**。对手看不到，裁判也看不到——他读的只有提交内容。
  模型可以在思考里说真话、在提交里撒谎，博弈才成立。
- **思考是一段 500 字说明**：说清「为什么这么选」。超出的部分默认折叠、展开可读，
  实时推演照常流、不丢尾。
- **引擎不理解规则语义**。它只保证同时性、完整性和留档；「这一手算不算赢」全交给裁判。
- **裁判看不到身份**。每轮重新映射 A/B/C，模型名、厂商名、队伍真名都不进 prompt。
- **没有角色扮演**。不加人格卡、不加人设前缀，模型说什么就是它自己。

## 规则怎么写

打开 `/rulesets`：左边用自然语言写规则，点「编译成蓝图」，模型把它转成结构化 JSON
（回合数、每轮提交项、评分维度与权重、胜负方式），你确认或手改后保存即可开局。

- `reveal: "secret"` 的槽位只有裁判看得到（暗标、底牌），`public` 的进下一轮公开战况。
- 权重随便写，保存时会自动归一化。
- 四条内置规则：`rulesets/dark-auction.md`（暗标竞地）、`rulesets/cricket-duel.md`（罐中论剑）、`rulesets/summit-clash.md`（山道四十阶）、`rulesets/interrogation-room.md`（八轮拷问）。
- 模型以自己的身份上场：不注入人格卡、不加角色设定，看到什么规则就怎么打。

### 战况面板（可选）

规则想让人看见血量、山道这类数字，就在蓝图里加 `board`，观战台会自动画出来：

```json
"board": {
  "meters": [
    { "key": "hp", "label": "血量", "kind": "bar", "min": -6, "max": 26, "init": 18, "threshold": 10 },
    { "key": "pos", "label": "山道", "kind": "track", "min": 0, "max": 40, "init": 0 }
  ],
  "marks": { "label": "雷位" }
}
```

- `kind` 三选一：`bar`（带临界线的条）、`count`（数字计数器）、`track`（0–max 赛道，最多一条）。
- 声明了 `board`，裁判每轮就要在 JSON 里多回一个 `state`（**本轮结束后的绝对值**，不是变化量）；
  有 `marks` 的再回一个 `marks`（当前仍在的标记格，比如没爆的雷）。
- 引擎只按声明范围裁剪数字，不理解它们的含义；裁剪/丢弃会写成 `anomaly` 事件。
- 裁判漏回读数的轮次：面板停在上一轮并标「读数缺失」，不会崩。
- 没声明 `board` 的规则（罐中论剑、暗标竞地）完全不长这个面板。

## 配置

`/setups` 里三段：

- **接入方** —— 名称、类型（openai / anthropic / gemini / mock）、base URL、Key 全部自填，
  可增删改。Key 落 `data/secrets.json`（0600），不入库、不进 git。
- **模型池** —— 点「拉取模型」从接入方拉回真实模型清单（OpenAI 兼容 `/models`、
  Anthropic `/v1/models`、Gemini `/v1beta/models`），再逐个勾「选手 / 裁判 / 启用」。
  代码里没有任何写死的模型。模型以自己的身份上场，不套角色设定。
- **裁判** —— 开局页从「裁判池」里指定谁坐在裁判席；默认「自动」，优先挑与选手不同接入方的模型。
  指定结果在开局瞬间冻结进 `matches.judge_json`，之后改配置、换池子都影响不到这一局。
  裁判与选手同接入方时会提示可能带自偏好，但不阻止。
- **思考强度** —— 每个模型单独配。点「校准」从 [models.dev](https://models.dev) 拉取该模型的
  能力卡（是否支持思考、可选强度、上下文与价格），然后在下拉里选档位。见下节。

## 提示词（全局内置）

`/prompts` 里改选手、裁判、规则编译器收到的 system 提示词，存库后对之后所有对局生效：

- **选手 system** —— 定位、规则、座位与输出协议。必须保留 `<<<THINK>>>`、`<<<SUBMIT>>>`，
  以及 `{{scene}}`、`{{briefing}}`、`{{team}}`、`{{mates}}`、`{{submitShape}}`。
- **裁判 system** —— 盲化视角下的判分说明。`{{format}}` 决定普通轮与加时轮各自的输出 JSON 骨架。
- **规则编译 system** —— 自然语言 → 蓝图的编译约束，`{{maxRounds}}` 等上限由引擎填。
- **全局附加指令** —— 非空时追加到选手与裁判 system 的末尾，留空即关闭。

保存时会拒绝缺占位符或缺协议标记的模板；「恢复默认」删掉存档，回到内置版本。
模板只负责措辞：动态事实（队名、座位、历史提交）仍由引擎注入，所以盲化与迷雾不依赖提示词。
正在跑的对局从下一轮调用起读到新模板，历史对局不受影响。

## 思考强度

同一个模型，档位不同，打法就是两个模型。所以强度是**模型级配置**，随对局快照冻结：

- **档位**（`none / minimal / low / medium / high / xhigh / max`）来自 models.dev 的
  `reasoning_options`；不同模型支持的档位不同，UI 只列它真正接受的。
- **落线方式**由 provider 决定，全部在 `src/providers/reasoning.ts` 里：
  OpenAI 兼容 → `reasoning_effort`（OpenRouter 走 `reasoning.effort`）；
  Anthropic → `thinking.budget_tokens`（档位换算预算，压到 `[1024, max_tokens/2]`——
  思考与正文共享 `max_tokens`，不给正文留余量就会得到一段空白回答）；
  Gemini 3.x → `thinkingLevel`，Gemini 2.5 → `thinkingBudget`。
- **优先级**：显式「预算」> 档位换算 > provider 默认（不传）。
- **不支持思考的模型**不会收到任何思考参数；models.dev 说该模型不吃 `temperature` 时，
  也不再发 `temperature`（GPT-5 这类会直接 400）。

数据源是公开的 `https://models.dev/api.json`（不需要 Key，进程内缓存 6 小时）。
要换镜像或离线包，设 `MODELS_DEV_URL`。校准只写本地 `models` 表——
历史对局读的是 `participants.model_json` 快照，改配置不会影响已打完的牌局。

## 开发规范

改代码前先读 `AGENTS.md`：六条硬约束、依赖方向、迁移政策、看门狗阈值，以及一张「踩过的坑」表。
提交前的三步检查也在那里。

## 命令

```bash
bun run dev         # 开发
bun run build       # 生产构建
bun test            # 引擎 / 协议 / 盲化 / 思考参数 测试（101 项）
bun run db:migrate  # 建表 + 同步内置规则
```

旧版（数值战斗）的数据库不兼容，`db:migrate` 会检测到 `games` 表并重建——
对局数据会清空，这是开发期的破坏式迁移。
